# Instructions de Versionnement pour les Agents AI (Claude & Antigravity)

> **Important pour les assistants IA (Claude, Antigravity) :**  
> Tous les fichiers situés dans le dossier `docs/paper/` (ainsi que dans ses sous-dossiers `actualites/`, `archive/`, etc.) font partie intégrante de la chaîne d'écriture et de documentation scientifique du projet. **Chaque fichier créé, modifié ou restructuré doit obligatoirement être versionné.**

---

## 1. Règles de Versionnement et d'Archivage

1. **Historique & Numérotation de Version dans les Fichiers :**
   - Tout document principal (`archive/MANUSCRIT_DETAILLE_2026_v1.6.md`, `MANUSCRIT_DETAILLE_2026_SLIDES.html`, etc.) doit indiquer explicitement son numéro de version (ex: `v1.0`, `v1.1`, `v1.2`, `v1.3`, ...) et sa date de mise à jour dans l'en-tête et l'historique des versions.
   - Les incréments de version suivent la convention :
     - `v1.x` : Révisions mineures (ajouts de sections, précisions techniques, réalignement de la démarche expérimentale, mise à jour de graphiques ou données).
     - `v2.0` : Refonte majeure du plan, modification d'hypothèses centrales ou soumission à revue.


2. **Le texte de l'article (`docs/paper/article/`) :**
   - Un chapitre = une section de l'article, en trois exemplaires : maître anglais dans `article/en/`, miroir français dans `article/fr/`, rendu LaTeX pour Overleaf dans `article/overleaf/`. Le nom est `NN_slug`, où `NN` **est** le numéro de section annoncé en 1.4 du chapitre 1.
   - Les trois fichiers d'un chapitre rédigé portent le **même numéro de version**. L'arbre par langue les éloignant, la vérification est outillée : `make paper-parite` sort en erreur si un maître a bougé sans son miroir, si une langue manque, ou si une section du plan n'a aucun fichier.
   - Un chapitre pas encore rédigé n'existe qu'en français, en `brouillon`, et le dit dans son en-tête. Ce n'est pas un écart de parité.
   - Le plan annoncé en 1.4 **fait foi** : `article/plan/PLAN.md` en est dérivé, jamais l'inverse, et tout écart se consigne dans `article/plan/README.md`.
   - Aucun instantané de version dans `article/` : les versions figées vont dans `archive/`.
   - Détail et état d'avancement : [`article/README.md`](file:///Users/yvesb/Documents/Projects/llm-agents-gama/docs/paper/article/README.md).

3. **Archivage des Versions Majeures/Intermédiaires (`docs/paper/archive/`) :**
   - Lorsqu'une version franchit une étape importante (ex: passage de `v1.2` à `v1.3`), une copie figée de la version antérieure doit être conservée dans le dossier `archive/` (ex: `archive/MANUSCRIT_DETAILLE_2026_v1.2.md`).
   - Ne jamais supprimer ni écraser destructivement les fichiers archivés.

4. **Suivi Git (Version Control) Obligatoire :**
   - Tout nouveau fichier créé (`.md`, `.html`, `.py`, `.json`, `.png`) doit immédiatement être ajouté à l'index Git (`git add <fichier>`).
   - Les commits doivent comporter un message explicite décrivant les modifications apportées aux manuscrits et slides.

5. **Rendus dérivés (`presentations/`) :**
   - Le manuscrit détaillé n'est plus le document maître : il est figé dans `archive/MANUSCRIT_DETAILLE_2026_v1.6.md` et son texte vit désormais chapitre par chapitre dans `article/`. La règle de parité qui le liait à ses planches n'a donc plus d'objet.
   - Les supports de `presentations/` sont des **rendus dérivés** des chapitres. Quand un chapitre change, la planche qui le présente se met à jour, chapitre par chapitre — et un support qu'on gèle rejoint `archive/` sous son numéro de version.

6. **Chiffre publié = chiffre recoupé.**
   - Tout chiffre entrant dans un document de `docs/paper/` est recalculé depuis sa source dans le dépôt — `scripts/progedo_logit/mode_choice_policy_metrics.json` (accuracy, LogLoss, matrice de confusion, importances), `scripts/progedo_logit/feature_spec.json` (contrat de variables), `docs/arch/score-synthesis.md` (renormalisation sur l'offre, témoin d'effectif), `docs/changelog.md` (temps terminaux, variantes mesurées) — et non recopié d'une version antérieure d'un manuscrit.
   - Les écarts constatés lors d'un recoupement sont consignés dans le **journal des corrections** (Annexe F de `archive/MANUSCRIT_DETAILLE_2026_v1.6.md`), jamais corrigés en silence.
